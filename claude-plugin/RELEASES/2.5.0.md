# secondbrain-db plugin v2.5.0

**Tracks `secondbrain-db` CLI v2.4.0** (external-sync bookkeeping). This
release teaches the plugin to drive the new `sbdb sync` commands.

## What v2.4.0 added on the CLI side

External-sync bookkeeping
([#63](https://github.com/sergio-bershadsky/secondbrain-db/pull/63)). sbdb
tracks docs that mirror to external services (Confluence, Jira, Notion,
Slack canvas) without ever making a network call. It owns the integration
configs (`.sbdb/integrations/*.yaml`), per-doc state sidecars
(`<doc>.integrations.yaml`), and drift detection; the actual pushing is the
job of an integration runtime. New commands: `sbdb sync check`,
`sbdb sync targets`, `sbdb sync state get`, `sbdb sync state set`. See
`docs/guide/sync.md` in the CLI repo.

## Plugin changes shipped here

- **New skill `secondbrain-db-sync`** — teaches Claude to be the integration
  runtime: detect drift with `sbdb sync check`, branch on the result, ask the
  user per doc, fetch the assembled payload with `sbdb sync state get`, push
  via the appropriate MCP server (Confluence / Jira / Notion / Slack), and
  record the outcome with `sbdb sync state set`. Encodes the hard rules:
  never hand-edit sidecars, never push without explicit confirmation, never
  call an external API without an MCP server.
- **Stop hook surfaces drift** — `hooks/sync-check.py` runs
  `sbdb sync check --format json` at end of turn and surfaces a one-line
  summary when docs are out of sync, alongside the existing `doctor heal` and
  integrity hooks. It never blocks and never pushes; `sync check` is
  local-only (no network, no credentials). Stays silent when no integrations
  are configured or nothing has drifted.
- **CLI reference updated** — `skills/secondbrain-db/reference/cli-reference.md`
  now documents the `sbdb sync` subcommands and exit codes.
- **Main skill cross-links** — `skills/secondbrain-db/SKILL.md` points to the
  new sync skill when external publishing comes up.

## Also in this release

- **CLI fix**: `sbdb sync state get` now emits `state` sub-object keys in
  snake_case (`last_push`, `doc_hash`, …) instead of Go field names. The
  sidecar state types gained JSON tags to match their YAML tags. This makes
  the documented `state.last_push.*` contract that the sync skill relies on
  actually hold.

## Compatibility

Requires CLI **v2.4.0 or later** (the `sbdb sync` command family). On older
CLIs the sync skill's commands will not exist and the Stop hook's
`sync-check.py` exits quietly (it only runs when `.sbdb/integrations/`
exists and an `sbdb` binary is on PATH).

## Notes

- sbdb still never talks to external services. All network I/O is the
  runtime's (Claude + MCP). The plugin adds the *teaching*, not the
  transport.
- Remote-drift detection requires the runtime to observe the external
  revision and record it via `sbdb sync state set --check-result`; sbdb
  never polls.
